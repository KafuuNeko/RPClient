# 系统提示词预设模板管理与升级方案

更新日期：2026-11-07。按用户最终确认的简化设计实施：整套切换、Long ID、默认预设不入库、当前选择存 SP、仅持久化修改项。本文描述当前实现。

## 使用行为

- 设置中的系统提示词入口进入预设管理页，支持搜索、新建、复制、修改名称与简介、启用、删除。
- 新建只填写名称和可选简介，不选择来源；新记录默认没有任何覆盖项，使用 `PromptType` 的默认值。需要沿用其他预设时使用复制操作。
- 启用仅在管理列表中操作。详情页直接展示提示词分组，不展示顶部说明、简介或启用按钮。
- 系统默认预设 ID 固定为 `-1L`。点击其提示词只提示“系统默认预设无法编辑”，不会自动弹出复制窗口。工具栏仍可主动复制整套预设。
- 自定义预设逐项编辑。未保存返回需要确认放弃；保存失败保留草稿；revision 冲突不覆盖其他页面的新内容。
- 新建与复制不自动启用。删除当前预设时先把 SP 选择切回 `-1L`，再删除数据库记录。

## 默认值与读取规则

`libs/prompt/PromptType.kt` 是默认值的唯一来源，每个枚举项包含稳定 `key` 与 `defaultValue`。不再保留独立默认值对象或冻结默认值副本。

| 情况 | 读取结果 |
|---|---|
| 预设 ID 为 `-1L` | 直接读取枚举默认值，不查询覆盖项 |
| 自定义预设存在对应条目 | 读取保存的完整原文，包括空串、空白和宏 |
| 自定义预设不存在对应条目 | 读取枚举默认值 |
| SP 中选择的自定义 ID 已不存在 | 回到 `-1L` |

保存时按原文与枚举默认值比较：相同则删除覆盖行，不同则插入或更新。对非空默认值保存空串仍会产生一条有效覆盖。新建不展开默认值；复制只复制来源已有的覆盖项，未知键也保留。

新增提示词类型只需扩展枚举、构建器与对应页面分组，既有预设自然回退该类型的默认值，不需要给每套预设补行。

## 数据结构

Room 版本保持 **6**，应用版本为 `20260404` / `2026.4.4`。直接更新此次尚未发布的 v6 schema，不增加 v7，也不改动 v1—v5 schema。

### prompt_presets

仅存自定义预设，系统默认没有数据库记录。

| 字段 | 类型 | 用途 |
|---|---|---|
| id | INTEGER PRIMARY KEY AUTOINCREMENT | Kotlin Long 自增 ID |
| name | TEXT NOT NULL | 名称，可重名 |
| description | TEXT NOT NULL DEFAULT '' | 可选简介 |
| revision | INTEGER NOT NULL DEFAULT 1 | 乐观锁版本 |
| createdAt | INTEGER NOT NULL | 创建时间 |
| updatedAt | INTEGER NOT NULL | 修改时间 |

不包含 kind、迁移状态或激活标记。

### prompt_preset_entries

| 字段 | 类型 | 用途 |
|---|---|---|
| presetId | INTEGER NOT NULL | 所属自定义预设 ID |
| promptKey | TEXT NOT NULL | PromptType 的稳定 key |
| content | TEXT NOT NULL | 与默认值不同的正文 |

联合主键为 `(presetId, promptKey)`。`presetId` 引用 `prompt_presets.id`，删除父记录时级联删除覆盖项。元数据更新使用 UPDATE，避免 REPLACE 触发级联删除。

### 当前选择

在 AppModel 中定义 `activePromptPresetId by longPref(default = -1L, commitByDefault = true)`。没有单独的选择或状态表。

Repository 合并 Room 列表与进程内选择流，生成包含虚拟默认项的页面列表。默认项仅用于显示，永不插入数据库。

## 旧版升级

`AutoMigration(5, 6)` 只创建两张表。`Upgrade20260404` 在业务升级阶段处理旧偏好。

- 若已存在 `activePromptPresetId`，说明新选择已经初始化或来自完整恢复，跳过旧配置重建。
- 使用固定旧键映射读取原先 23 个提示词。存在的值必须为字符串，不裁剪空白，不改变宏；缺键和等于默认值的项都不写覆盖行。
- 有旧提示词保存记录时创建一套本地化的“自定义预设1”，固定首次迁入 ID 为 `1L`，元数据与覆盖项在同一事务提交。
- 没有任何旧提示词保存记录时不创建自定义预设，选择 `-1L`。
- 数据库提交后同步保存 SP 选择，成功后由已有 AppUpgradeManager 推进版本检查点，再清理旧提示词键。
- 数据库提交后、SP 保存前中断，重试复用已存在的迁入记录，不覆盖正文。SP 已保存后重试直接跳过导入，即使用户已经删除迁入预设也不会重建。
- 不清理其他全局偏好；迁移失败保留旧值。沿用现有启动失败后下次启动重试的流程，不增加启动框架或状态表。

旧版未保存过的默认值没有历史原文，缺项按当前枚举默认值解析，与原 getter 的缺键行为一致。

## 生成与优先级

单聊、群聊、故事及摘要构建器接收本轮的完整 `PromptTemplateSnapshot`。快照在调用入口捕获，生成期间切换或编辑预设不影响已经构建的请求。

- 单聊空输入替换与实际请求共用快照，关联自动摘要继续使用该快照。
- 群聊同一发言批次共用快照，新的自动批次可读取新选择。
- 摘要窗口扩展与 Token 预算探测共用同一快照。
- 保留已有角色、会话覆盖优先级及 `{{original}}` 语义；Provider 参数和其他全局设置不进入模板。

## 完整备份

完整备份仍使用 v3。两张业务表由通用表导出保存，激活 ID 随原有 SharedPreferences 目录保存。

- 旧备份先完成数据库结构迁移，再只读取归档暂存目录中的旧偏好，迁入自定义预设并把选择写回暂存 SP。
- 新备份直接读取暂存 SP 的选择；对应预设被手工删除时改为 `-1L`，不创建默认数据库记录。
- 转写选择键时保留其他偏好的类型、字符串、空白和集合。不读取设备在线偏好来补备份数据。
- 所有迁移、XML 校验和选择修复都在替换在线数据前完成。错误格式或类型导致恢复失败，在线数据保持不变。
