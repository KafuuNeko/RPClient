# 图片预估器调研与实现

核对日期：2026-11-15。

## 结论与覆盖边界

当前实现覆盖官方已经公开的主流图片输入规则，并使模型配置中的画质、请求编码与本地估算保持一致。未知模型使用面积代理，不能把代理值视为可证明的安全上界，也不能把本地估算当作服务端实际计费。

| 模型范围 | 本地策略 | 自动处理与限制 |
| --- | --- | --- |
| GPT-4o、GPT-4.1、GPT-4o-mini | 各自的 Tile 基础值与切片系数 | low 只计基础值，auto/high 计切片 |
| GPT-5、GPT-5.1、OpenAI o1/o3 | 独立的 Tile 系数 | 不与 GPT-4o 混用系数；包含仍需兼容的旧型号 |
| GPT-4.1-mini、GPT-5.2 | 32px Patch，各自乘数 | 使用官方相应边长和缩放预算 |
| GPT-5.4 系列 | 按档位选择 Patch 规则 | auto 对应 high，low 的预算可能比 high 更高 |
| GPT-5.5、GPT-5.6、GPT-6 Astra | 各自的原始细节与缩放规则 | auto 按原始细节处理；拒绝上限与缩放预算分开 |
| Claude 标准／高分辨率 | 28px Patch 与官方整数缩放算法 | 包含 Opus/Sonnet/Haiku 5.5、Fable/Mythos 5.2 等已核实名称 |
| Gemini 3／4 | 分辨率档位的公开视觉预算 | 现代协议在图片 Part 写入分辨率，自动继承原有全局参数 |
| Gemini 2.5 | 固定低／中档位与 Pan & Scan 代理 | 只写全局分辨率；内容相关的高档位计数标为估算 |
| GPT-6.1、GPT-6 Luna、Grok、未知网关模型 | 通用面积代理 | 未找到充分公开的独立图片计数规则，保留估算性质 |

OpenAI 的图片规则表未单列 GPT-6.1 和 GPT-6 Luna。不能仅凭同属 GPT-6 就复用 Astra 的处理规则。确切计数可由用户另外使用官方计数接口核实，本地客户端不会为估算自动上传图片或发起额外付费探测。

## 分层与数据边界

- `LLMImageReference` 保持纯资源描述，只包含 UUID、格式、尺寸和字节数。
- `ImageQuality` 与 `ImageInputOptions` 表达通用请求设置，包含自动、低、中、高、超高和原始细节；不包含任何服务商字段或网络枚举值。
- `ImageInputCapabilities` 集中提供协议和模型可选范围，编辑页和实际发送复用同一策略；界面不引用服务商估算器。
- `ImageInputPreferences` 负责设置存储及协议参数解析，服务商字段只在适配层转换。请求编码器和估算器读取同一份解析结果。
- `OpenAiImageProfiles` 集中登记已公开的模型规则，计数和输入限制校验复用相同的缩放计算。
- `ImageModelAliases` 集中维护模型与规则对应关系，支持原生快照和已知 OpenRouter 命名；不根据任意品牌前缀推测未来模型。

模型画质设置保存在既有配置扩展的客户端节点，无需变更数据库结构。该节点在合并请求时移除，不能发送到服务端。手选图片预估器只影响本地算法，不改变图片能力、画质或服务端限制。

## 画质与兼容行为

- 原有配置默认使用自动画质，Gemini 已有的全局分辨率继续生效。
- 新的画质控件按实际协议和已核实型号显示支持的范围；Claude 原生协议没有对应质量参数时不显示该控件。
- 画质设置仅控制模型对图片的处理，不解除本地压缩、尺寸、字节数及请求图片数量限制。
- 调整模型画质不会修改已经存储的图片，也不会把附件压缩模式等同于服务端的原始细节档位。
- Gemini 的 snake_case 与 camelCase 字段在明确协议的边界规范化。同义字段冲突被拒绝，不能绕过系统消息或输出参数保护。
- OpenAI 超过处理后单图 Patch 上限时，在生成请求文件前给出受控错误；不隐式修改用户选择的画质。
- Grok 原生配置校验其公开支持的 JPEG/PNG 格式；不把格式错误学习为模型没有视觉能力。

## 估算可信度与风险

- 未知模型不再对所有尺寸固定使用 4096 Token。通用策略保留最低预留，并根据 32px Patch 数及公开规则中的较大乘数估算面积开销。
- 这一策略只改善大图明显低估，不保证适用于任意未来模型、私有网关或服务端预处理。
- Gemini 2.5 的 Pan & Scan 依赖图像内容，高档位采用代理预算，不能声明精确。
- 兼容协议不自动继承服务商原生画质参数。已识别的 Gemini／Claude 经其他协议调用时保持默认处理，不把 detail 猜测为原生分辨率；相应计数保留代理性质。
- 输入统计会合并图片和文本的可信度；未知图片算法不能因文本编码器已知而被误标为模型感知。纯文本统计维持原有策略。
- 服务端返回的 usage 只能校正生成后的用量记录，不能替代发送前预算。
- 本次核实的是公开规则、离线公式与协议编码，没有使用真实 API Key 或用户图片进行付费推理验证。
