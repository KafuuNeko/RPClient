# 主题样式与自定义页面背景实现方案

调研日期：2026-10-10。代码基线：`283f8a5`。本文为实现建议，未修改应用代码，未进行设备性能实测。涉及图片尺寸、滑块范围、透明度和缓存容量的数值均为待验证的初始配置。

## 推荐结论

- 将外观拆为“明暗模式、配色方案、内容样式、页面背景”四个独立维度。保留现有默认外观，用户只换主题时不重置背景图片和模糊度。
- 首批提供经典蓝、樱花粉、森林绿、暮光紫、暖纸棕、石墨灰六组浅色／深色配色，并开放 Android 12+ 系统动态配色。纯黑作为深色模式的附加选项。
- 首版支持单聊、群聊、故事编辑器分别设置默认背景：本地选图、裁切位置、模糊度、背景遮罩、恢复默认。后续增加某个会话或某篇故事的独立覆盖。
- 三页共用 `PageBackdrop` 和背景处理能力；背景图片单独模糊，文字、头像、消息附件、输入框保持清晰。
- 静态图片优先采用“后台 CPU 预处理 + 内存／磁盘缓存”，覆盖 Android 8+；滑块使用低分辨率预览，停止拖动后生成最终图。Android 12+ 原生 GPU 模糊作为可选优化，先以真机数据决定是否引入第二套渲染路径。
- 主题轻量偏好继续使用 Kotpref；背景配置放 Room，图片复用 `FileRepository`，派生模糊图只放缓存。不得将背景接入消息附件或模型请求。

## 主题样式调研与选择

### 外观维度

| 维度 | 建议选项 | 生效范围 |
| --- | --- | --- |
| 明暗模式 | 跟随系统、浅色、深色 | 全应用，沿用 `AppThemeMode` |
| 配色方案 | 六组预设、系统动态配色；后续自选主色 | 全应用，保持与明暗模式独立 |
| 内容样式 | 现有气泡、平铺对话、阅读样式 | 单聊／群聊；故事页沿用正文编辑器 |
| 页面背景 | 主题底色、本地图片；后续内置渐变／纹理 | 三类页面独立保存 |
| 阅读调节 | 图片模糊、背景遮罩、内容卡片不透明度 | 当前背景配置，明暗模式可采用不同默认遮罩 |

SillyTavern 的官方文档区分 Flat、Bubbles、Document 三种聊天呈现，也提供颜色、模糊、字体和主题保存能力。这说明“更多主题”可以同时包含配色和内容呈现；它的 UI 面板模糊与本需求的静态背景图模糊不是同一渲染对象。RPClient 可借鉴设置分类与预览体验，使用原生 Compose 实现相应样式，不直接兼容 CSS 主题文件。[SillyTavern UI Customization](https://docs.sillytavern.app/usage/core-concepts/uicustomization/)

### 候选配色

下列颜色是视觉方向／种子色建议，不是可直接用于所有控件的最终色值。每组都要生成并验证完整浅／深色方案。

| 名称 | 颜色方向 | 浅色氛围 | 深色氛围 | 适合场景 |
| --- | --- | --- | --- | --- |
| 经典蓝 | 沿用当前品牌蓝 `#3B66F5` | 冷白、蓝色重点 | 深灰蓝 | 保持现有用户体验，作为默认 |
| 樱花粉 | 柔和玫瑰 `#B85C83` | 暖白、低饱和粉 | 暗玫瑰灰 | 角色对话、人物插画背景 |
| 森林绿 | 鼠尾草绿 `#527A60` | 灰白、柔绿 | 暗森林绿 | 自然场景、长时间阅读 |
| 暮光紫 | 雾紫 `#7C65A9` | 淡紫白 | 暗紫灰 | 奇幻、夜景、科幻故事 |
| 暖纸棕 | 纸张棕 `#8A6745` | 米白、暖灰 | 深棕灰 | 故事编辑和文档式聊天 |
| 石墨灰 | 中性灰蓝 `#606873` | 简洁灰白 | 石墨灰 | 图片较复杂、强调正文的场景 |
| 系统动态 | 系统壁纸配色 | 系统生成 | 系统生成 | 希望与手机外观一致的用户 |

纯黑建议为 `amoledDark` 附加开关：仅深色生效，背景置黑，卡片保留层级，并重新验证文字、边框和禁用态。不要把纯黑效果包装成与所有配色互斥的单独主题。

### 配色实现方案比较

| 方案 | 收益 | 代价与边界 | 建议 |
| --- | --- | --- | --- |
| 预生成完整 ColorScheme | 零运行时配色依赖、结果可控、全系统版本可用 | 增加一个预设需维护浅／深两套颜色 | 首版主方案 |
| 系统 `dynamicLightColorScheme`／`dynamicDarkColorScheme` | 已有代码基础，与系统壁纸一致 | Android 12+；低版本回退经典蓝 | 首版开放独立选项 |
| Material Color Utilities／MaterialKolor | 从自选色或图片生成整套配色 | 新依赖或源码维护、Kotlin／Compose 兼容校验、需要对比度验证 | 后续支持自定义主色时采用 |
| 任意颜色编辑器／主题文件导入 | 高度自由、便于分享 | 非法颜色、缺失字段、版本兼容和可读性处理明显增加 | 后续高级功能 |

Android 官方支持通过 Material Theme Builder 导出 Compose 配色；系统动态配色要求 Android 12+。它读取系统配色，不会自动根据用户在 RPClient 内选择的背景图取色。[Material 3 in Compose](https://developer.android.com/develop/ui/compose/designsystems/material3)

图片取色如后续加入，应在图片导入完成后异步执行一次，持久化种子色，并由用户主动选择“从此背景生成主题”。Material Color Utilities 提供量化、颜色评分和配色生成模块；MaterialKolor 提供 Compose 封装和图片取色入口。本文未验证其具体版本与仓库当前 Kotlin／Compose 组合的编译兼容性，不建议直接追随最新版升级。[Material Color Utilities](https://github.com/material-foundation/material-color-utilities)、[MaterialKolor](https://github.com/jordond/MaterialKolor)

### 样式 token

- `ThemePalette` 保存稳定 ID 和浅／深 `ColorScheme`。新配色应覆盖实际使用的 `surfaceContainer*`、`tertiary*`、`errorContainer*` 等角色，避免部分组件仍显示库的默认色。
- `AppAppearance` 聚合 `themeMode`、`paletteId`、`amoledDark`。`AppThemeManager` 提供单一状态快照，`CoreActivity` 仅增加必要传参。
- `ConversationStyleTokens` 定义用户／角色消息底色与文字色、圆角、间距、边框、元信息颜色。首版值对应现有气泡；平铺和阅读样式后续替换 token 与必要布局。
- `PageSurfaceTokens` 定义消息卡片、故事正文、顶部栏、输入区的容器色与不透明度。只调背景／容器颜色的 alpha，不对整个内容节点调用 `Modifier.alpha()`。
- 角色身份色和错误／成功状态色保持明确语义，不强行统一成主题主色；检查硬编码强调色在浅／深主题上的表现。
- 主题切换不以主题 ID 作为整个页面的 `key`，不触发 Activity 重建，保留消息滚动位置、草稿和故事光标。

## 背景设置体验

### 入口与预览

全局设置增加“外观”，内含配色卡片以及“对话背景、群聊背景、故事背景”三个入口。设置主体放独立 `feature/appearance`，Main 只提供导航。

背景编辑页建议包含：

- 对应页面缩略预览，展示消息或正文、顶部栏和输入区，允许切换浅／深预览。
- “选择图片”“替换图片”“使用主题底色”；导入中显示状态，选图取消不改变已保存设置。
- 模糊度 `0–100%`：`0` 为清晰图，初始建议 `25%`。
- 背景遮罩：用户文案说明数值越高，图片越淡、文字越清楚；浅色使用浅色主题底色遮罩，深色使用深色主题底色遮罩。
- 图片位置：默认等比例居中填充，可调整焦点位置；首版不需要复杂图像编辑器。
- “高级”内提供内容卡片不透明度；默认消息卡片约 `92%`，故事正文约 `96%`，最终值必须结合实际图片校验。
- “应用”和“取消”：拖动只改预览草稿；松手生成最终预览，点击应用后才持久化。取消释放新导入草稿，保留旧背景。

主界面保留实色或足够不透明的顶部栏、输入区和弹窗。用户将图片设为清晰时，内容卡片仍承担可读性保护，不能仅靠模糊保障文字对比度。

### 作用域与继承

首版只有三类页面的默认配置。后续在单聊设置、群聊设置、故事设置中增加“当前页面背景”，支持以下继承关系：

| 优先级 | 配置 | 语义 |
| --- | --- | --- |
| 高 | 当前会话／当前故事覆盖 | 对一个实体单独设置 |
| 中 | 对话／群聊／故事默认 | 对该类页面共同生效 |
| 低 | 主题纯色底 | 没有图片配置时的默认表现 |

- 明确区分 `INHERIT`、`SOLID`、`IMAGE`。实例“恢复默认”删除覆盖并继承；实例“使用主题底色”显式停止继承图片。
- 按整个背景配置继承，不逐字段拼接，避免图片取自默认配置而模糊度意外残留。
- 故事按 `storyId` 保存，章节切换不改变背景；逐章节背景列为后续独立需求。
- 图片失效时显示主题底色并保留可修复的配置，不自动换成另一张继承图片；用户主动替换或恢复默认。
- 首版可以提供“将此背景应用到全部三类页面”，但每个配置必须有自己的文件索引引用。

## 模糊技术选型

### 方案对比

| 路径 | 系统兼容性 | 优点 | 主要代价 | 结论 |
| --- | --- | --- | --- | --- |
| 仅 `Modifier.blur`／`RenderEffect` | 原生模糊为 API 31+ | 实现短，现代设备可即时更新半径 | API 26–30 不满足用户调节模糊度的要求；占用图形层 | 不可作为唯一方案 |
| API 31+ GPU，低版本 CPU | 可覆盖 API 26+ | 新设备拖动预览流畅 | 两套算法、边界与视觉强度可能不同，测试面更大 | 可选优化路线 |
| 全版本 CPU 生成静态模糊图并缓存 | 可覆盖 API 26+ | 结果一致、滚动时只绘制图片、容易控制后台任务 | 冷生成延迟和中间位图内存；需要可靠的取消与缓存 | 推荐首版 |
| Haze 等实时背景采样 | 依赖所选版本的后端支持 | 适合玻璃面板、对背后滚动内容实时模糊 | 引入捕获链路和版本兼容工作；静态壁纸用不到大部分能力 | 真正需要磨砂面板时再评估 |
| 新增 RenderScript 管线 | 平台 API 已弃用 | 有旧示例可参考 | 维护与构建工具支持风险 | 不采用 |

Compose 官方明确说明 `Modifier.blur` 在 Android 12 以下被忽略，且会建立额外图形层。它模糊的是该节点自身及其内容；把它挂在整个页面上会连文字一起模糊。[Compose blur API](https://developer.android.com/reference/kotlin/androidx/compose/ui/draw/blur.modifier)

RenderScript 自 Android 12 起弃用。Google 提供过 CPU replacement toolkit，但该仓库已于 2024-12-12 归档；不将它视为仍持续维护的首选依赖。Haze 官方仓库在本次调研时将 2.0 标为 beta，适合作为未来效果能力的候选，不能直接套用某个旧版本的兼容性结论。[RenderScript 迁移指南](https://developer.android.com/guide/topics/renderscript/migrate)、[Replacement Toolkit 仓库](https://github.com/android/renderscript-intrinsics-replacement-toolkit)、[Haze 仓库](https://github.com/chrisbanes/haze)

### 推荐的静态处理流程

- 导入并校验图片，修正 EXIF 朝向，生成保留长宽比的标准源图。模糊永远从标准源图计算，不对上次模糊结果再次模糊。
- 按稳定的背景显示区域和焦点位置裁切，依模糊强度选择处理分辨率，执行可分离 box blur 多次近似高斯模糊。纯 Kotlin 实现可避免新增 NDK；具体算法质量和速度通过原型验证。
- 将结果交给 `PageBackdrop`；遮罩在 Compose 单独绘制，不烧录进图片，因此切换深浅主题或遮罩强度无须重新模糊。
- 原图导入、解码和写缓存使用 IO 调度器；像素计算使用 Default 调度器，并限制背景处理任务并发，避免争抢生成和 UI 资源。
- 拖动滑块时只生成长边约 `360–512px` 的低分辨率预览，以合流／限频方式处理最新值；初始间隔可从 `80–120ms` 测试。停止拖动后生成最终尺寸。
- `collectLatest` 只负责发出取消信号；CPU 循环仍需周期性检查取消，并使用请求 generation ID 丢弃过期结果，防止旧任务回写覆盖最新预览。
- 清晰图使用单独路径，`blur=0` 不进行降质模糊。弱模糊不能过度降采样，否则滑块刚离开零就出现明显马赛克或清晰度跳变。
- 边缘采用 clamp 或镜像扩展，处理后裁回目标区域，避免透明／黑色边缘；带 alpha 的源图应正确处理预乘 alpha，避免暗边。

显示给用户的是百分比，内部可先映射到 `0–32dp` 的等效模糊强度。若按视口裁切后的位图处理，处理半径应按密度与降采样比例换算：

```text
显示半径 px = 32 × blurPercent / 100 × displayDensity
处理半径 px = 显示半径 px × 处理图宽度 / 对应显示区域宽度
```

这是建议的强度标尺；box blur 的 kernel 不能未经标定就等同于 RenderEffect 半径。若未来增加 GPU 后端，应使用同一测试图片校准强度映射，避免系统版本之间同一百分比观感不同。

### 缓存与内存

- 持久源图建议长边上限从 `2048px` 开始验证；模糊图根据目标尺寸和强度进一步降采样。先读取图片尺寸，校验输入字节数与像素上限，再采样解码，不完整解码超大图。[Android 大图加载指南](https://developer.android.com/topic/performance/graphics/load-bitmap)
- ARGB_8888 的 `2048 × 2048` 位图像素数据约占 `16MiB`；源图、输出、中间数组并存可能成倍增长，不能把压缩文件大小当作内存占用。
- 仅保留当前页需要的可显示结果；后台 Activity 不继续计算预览。内存缓存按字节设限，低内存时释放可重建条目，不在仍被 Compose 绘制时手动回收共享位图。
- 缓存键至少包括内容 hash、裁切／焦点、目标像素尺寸、模糊强度、算法版本和必要的密度换算结果。主题颜色与遮罩不参与已分离的模糊图缓存。
- `cacheDir/backgrounds/` 存派生结果，采用容量上限和 LRU 清理；源图由私有文件仓库管理。只将稳定结果写磁盘，不给每次滑块变化生成永久文件。
- 缓存清空、文件损坏或进程重启后可由源图重建。生成中保留旧的合适预览；内存不足时降采样重试，最终失败回退主题底色并提供本地化提示。
- 使用固定的页面背景锚定区域，键盘只改变内容布局，不反复改变背景裁切和缓存键；旋转、分屏等真实窗口变化才更新目标规格。该行为须在三页现有 insets 结构中真机验证。

## 图片选择与文件生命周期

### 选择、校验与应用

使用 `ActivityResultContracts.PickVisualMedia(ImageOnly)`。官方 Activity 库在 Photo Picker 不可用时可回退 `ACTION_OPEN_DOCUMENT`；不需要为选择一张背景申请整个相册的访问权限。选择结果 URI 默认访问期有限，应及时复制进私有暂存；如处理必须跨重启延续，再按支持情况申请持久 URI 权限。[Android Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker)

建议沿用现有 MVI：Compose 发出选图 Intent，ViewModel 发出 ViewEvent，Activity 启动选择器并回传结果；Background Runtime 在后台读取和校验，界面只接收预览状态。

- 首版明确支持静态 JPEG、PNG、WebP；透明图保留 alpha，并以主题底色托底。其他格式仅在有可靠解码与校验路径后开放；不要只凭文件扩展名判断。
- 新建 `BackgroundImagePolicy` 管理输入大小、像素限制、输出尺寸和缓存预算，不使用用户的 `ImageSendSettings`，避免发送图片设置改变背景效果。
- 导入使用有界流复制；现有 `saveFile()` 通用入口并不提供本功能所需的完整图像校验，应调用暂存／生成能力并落实背景专用限制。
- 标准化重编码完成后不保留位置等无关 EXIF 元数据。用户选择前的原始相册文件不修改。
- `Apply` 时先确认预览对应当前草稿，然后通过 `FileRepository.mutate` 发布文件，在同一个 Room 事务内建立配置引用并释放旧的专属索引。数据库或生成失败均保留原已提交配置。
- `Cancel` 释放本次准备的文件；崩溃遗留草稿由既有 staging 清理机制收尾。草稿恢复只保存 handle 和设置，不把 Bitmap 或真实文件路径写进 SavedState／UiState。

### 必须保持的引用规则

当前 `FileRepository` 根据 `files` 索引数量判断物理 hash 是否可回收，因此“同一物理内容”与“同一 file UUID”不是同一概念。

- 每条独立背景配置持有自己的 `files.uuid`；相同图片可共享 hash 对应的物理字节。
- “应用到全部页面”、未来会话分支／复制，均在事务内使用 `copyReference` 创建新索引，不能让多个配置直接复用一个可能被其中一方删除的 UUID。
- 背景表对 `fileUuid` 建唯一索引与外键约束，防止多个所有者意外共享专属引用；新配置指向现有头像／消息图片时也必须先复制引用。
- 删除背景先解除配置引用，再在同一文件事务内移除它的索引；物理文件是否删除继续交给 FileRepository 和读取租约判断。
- 缓存可丢弃，源文件索引不可依赖缓存恢复。外观模块的删除和复制不调用消息附件删除／发送流程。

## 数据模型与分层

### 持久化

Kotpref 仅新增少量全局外观偏好：`themePaletteId`、`amoledDark`；继续保留原有 `themeMode`。未知配色 ID 回退经典蓝，旧用户没有新增键时外观保持原样。不要把所有会话的背景塞进一个偏好 JSON Map。

建议新增 Room `page_backgrounds` 表。首版仅写三条页面默认记录，模型预留实例作用域：

| 字段 | 建议含义 |
| --- | --- |
| `scopeType` | `CHAT_DEFAULT`、`GROUP_DEFAULT`、`STORY_DEFAULT`；后续 `CHAT_SESSION`、`GROUP_SESSION`、`STORY` |
| `scopeId` | 默认作用域为 `0`；实例作用域为对应业务主键，与 scopeType 组成主键 |
| `mode` | `SOLID` 或 `IMAGE`；无记录表示继承／系统默认 |
| `fileUuid` | `IMAGE` 必填，指向本配置专属 `files.uuid`；`SOLID` 为空 |
| `blurPercent` | `0–100` 整数，Repository 校验／钳制异常值 |
| `scrimLight`／`scrimDark` | 浅／深主题遮罩强度，范围 `0–1` |
| `opacity` | 故事正文容器不透明度，范围 `0–1` |
| `bubbleOpacity` | 单聊／群聊气泡独立不透明度，范围 `0–1` |
| `topBarOpacity`／`bottomBarOpacity` | 菜单栏／底部操作栏各自独立的不透明度，范围 `0–1` |
| `focalX`／`focalY` | `0–1` 归一化焦点位置；默认中心，保持填充比例 |

多态作用域不能直接用一个外键约束三种业务表。增加实例覆盖时，必须在各 Repository 的删除／分支事务里同步维护，并校验实体存在；不能依赖级联删除自动解决。首版只实现默认作用域，不提前改动会话删除逻辑。

### 职责划分

| 模块 | 职责 |
| --- | --- |
| `feature/appearance` | 设置与背景编辑、预览草稿、Intent／ViewEvent；复用同一编辑界面，按页面类型展示预览 |
| `libs/theme/AppThemeManager` | 全局主题偏好、当前外观 StateFlow |
| `libs/room/repository/PageBackgroundRepository` | 背景配置查询、继承解析、文件与数据库事务 |
| `libs/appearance/BackgroundImageRuntime` | 校验、方向修正、采样、模糊、缓存和取消；可拆出纯像素算法 |
| `ui/theme/ThemePalettes` | 预设配色及主题 token |
| `ui/widgets/PageBackdrop` | 绘制已解析图片、主题底色、遮罩；不访问 Repository 或做图片 IO |
| 各页面 ViewModel | 观察配置并请求渲染资源，将结果转成 `PageBackgroundUiState` |
| `RPClientApp` | 注册 Repository、Runtime、Manager；Activity ViewModel 沿用当前创建方式 |

`PageBackgroundUiState` 应与加载／可用／失败状态对应，保存 UI 安全的标识、已准备的图像引用和展示参数。底层 Runtime 返回平台位图或资源结果，Compose 专有类型只在 UI 适配层出现。不会把 ViewModel、Activity、文件句柄或数据库 Entity 直接暴露给绘制组件。

Room 观察与图片任务生命周期绑定页面可见状态；消息的每个流式 token 不改变背景请求 key，也不重新解码背景。

## 三页接入细节

统一绘制顺序为：主题兜底色 → 静态背景图片 → 主题遮罩 → 消息／正文及交互控件。图片放在滚动列表之外，不作为 LazyColumn item。

| 页面 | 必要修改 | 必须保持的行为 |
| --- | --- | --- |
| 单聊 | `ChatNormal` 引入外层背景，处理根 Column 实色底，消息 Surface 使用对应 token | 历史分页、自动跟随、软键盘滚动补偿、消息选择与编辑 |
| 群聊 | `GroupChatNormalView` 的 Scaffold 使用透明容器让外层图可见；成员栏／输入区保留可读底板 | 发言者选择、头像／状态标识、成员横向滚动、流式消息 |
| 故事 | `StoryEditorScaffold` 接背景；`StoryTextEditor` 的正文 Surface 按配置设置底色 alpha；所有布局分支共用 | 以 chapterId 记忆的 TextFieldState、selection／composition、自动保存 revision、撤销与流式续写 |

- 无图片时使用主题底色，各栏位透明度仍然生效，不增加图片／模糊图层。
- 不把背景包在故事 `BasicTextField` 的 key 内；改变主题、模糊度、透明度均不得替换编辑器状态。
- 浅／深色切换只改遮罩与主题 token；背景图片 hash 不变，缓存不因主题切换失效。
- 故事大纲页、会话设置页、弹窗先保留普通 Material 表面，不盲目传播透明度到整个应用。
- Edge-to-edge 的状态栏／导航栏沿用主题规则，并保证背后有稳定底色或遮罩；不得仅根据未知图片亮度假定图标始终可读。
- 平铺／阅读式聊天后续接入时，应逐项保留消息操作、编辑入口、引用／代码块与可选择文本。群聊不能隐藏必要的发言者身份。

## 可读性、备份与边界

### 可读性

普通文本以至少 `4.5:1` 对比度作为设计验收目标，大字可采用 `3:1`。这是借鉴 WCAG 的视觉标准，不表示任意透明度与任意背景图片组合天然达标。[W3C Contrast Minimum](https://www.w3.org/WAI/WCAG20/Understanding/contrast-minimum.html)

- 内置主题验证正文、链接、引用、代码块、时间戳、禁用态和选区；半透明容器需验证与背景合成后的颜色。
- 预览覆盖高亮照片、深色图片和高频纹理。模糊不能保证明暗对比，遮罩与内容底板必须独立存在。
- 各透明度滑块可归零恢复不透明；预览显示文字与底板的组合，不能宣称固定 `92%` 已保证所有背景情况下的对比度。
- 系统字体放大、TalkBack 滑块数值、触摸目标尺寸、焦点和软键盘都属于验收范围。背景图为装饰元素，不重复朗读。

### 备份与导出

- Android Auto Backup 当前规则未排除正式 `app_repository` 资源；新增源图与 Room 配置需要一起验证恢复，不能仅凭规则推断迁移已经成功。
- 背景源图属于用户数据，派生图放 `cacheDir`，不扩大正式备份体积；继续排除 staging。大图体积限制也应考虑整体备份体积。
- 现有单聊／故事归档首版不自动携带背景图片，导入后使用接收设备的页面默认配置。将来要随归档迁移时，应设计可选 appearance 字段、图片去重载荷、版本兼容和“包含外观”选项。
- WebDAV 后续落地时，将新表、全局主题偏好和被引用的源图加入快照与恢复校验；不导出缓存或真实本地路径。
- 背景图片仅用于本地显示，不进入 Prompt、Token 估算、消息附件、模型请求或请求日志。

### 模糊容器阴影修正

- 阴影位于模糊壁纸、容器底色和前景内容整体下方，避免半透明容器自身的投影覆盖壁纸，产生内部横线。
- 使用带阴影的纯白壁纸容器进行像素回归，验证内部不出现暗线；保留原有坐标对齐、圆角裁切和模糊关闭测试。
- 背景修改确认复用 `AppActionListDialog`，统一浅深色容器、图标动作与危险操作配色。

### 内容区设置统一

- 三类页面的设置名称统一为“内容区透明度”和“内容区模糊度”，沿用已有持久化字段与 Room v5，不重置用户参数。
- 对话内容区覆盖消息、消息操作区及角色介绍卡，介绍卡内状态标签使用独立的高对比前景样式；群聊成员卡也归入内容区。
- 消息、介绍卡、思考块和相关操作容器移除装饰描边；群聊选中态与故事生成态边框保留功能含义，并随对应内容区不透明度衰减。

### 圆角与信息标签修正

- 局部壁纸先在隔离图层内合成主题底色、图片和遮罩，再统一圆角裁切，避免多次抗锯齿混合让主题底色在边角渗出。
- 自定义半透明表面不绘制外侧投影，不透明表面保留原有阴影；移除角落类似描边的残余轮廓。
- 角色介绍卡的消息数、世界书与流式状态使用实色语义表面、高对比文字和自动换行布局，不随壁纸透明度降低信息可读性。
- 新增覆盖浅深主题与阴影参数的逐像素圆角回归，旧实现可在关闭阴影的深色主题下复现残边。

### 通用页面背景与区域外观

- 外观设置新增「通用页面」，支持独立图片、图片模糊／遮罩／位置，以及菜单栏、底部操作栏、内容区各自的透明度和模糊度。仍采用静态壁纸派生图，不捕获或模糊前景文字、按钮和动态内容。
- 通用背景由 Activity 的背景 ViewModel 随可见生命周期订阅，适用于首页、设置、资源列表／编辑、创建页、日志、统计、JSON 查看及图片裁剪等页面。关于页和配色主题页不订阅通用背景，保留原本展示效果；外观编辑器只在预览中展示草稿。
- 普通页面通过 `AppPageScaffold` 标记顶部／底部槽位，`AppSurface` 和 `AppCard` 装饰对应区域。首页浮动底栏、编辑标签栏及裁剪工具栏显式指定区域。重复画布底色让出壁纸，独立输入区补充内容底板；卡片内部的标签、图标和按钮不重复套用效果，弹窗与页面背景坐标隔离。
- 对话、群聊、故事页的所有区域透明度和模糊度均为零时，区域外观跟随通用设置。这里的零透明度对应持久化不透明度 `1`，不以图片参数的默认模糊 `25` 或遮罩 `0.25` 阻断跟随。
- 跟随区域外观时，有独立背景图就保留其图片、全图模糊、遮罩和焦点；没有独立背景图就使用通用背景图及其图片参数。任一区域透明度或模糊度非零，则使用该页完整独立配置。菜单栏、底部栏和内容区不进行逐字段混合继承。
- `observeEffective` 只解析实际显示配置，编辑与保存仍使用原始配置。预览使用已解析的配置，保存不会将通用图片索引或区域值复制到专用页面；删除通用图片不会释放其他页面自己的图片。独立设置全部归零后会重新跟随最新通用设置。
- 通用内容区映射到对话／群聊原有气泡字段，以及故事页原有内容字段。对话设置、群聊设置、故事设置／章节大纲均使用所属页面的有效配置；有独立图片但区域设置全部为零时，也保留所属页面图片并继承通用区域外观。
- 使用现有背景表新增 `general` 页面键，无结构变更、无新迁移，Room 保持版本 `5`。新增文案同步全部 13 个语言资源目录。
- Debug 应用和设备测试包构建通过；API 37 模拟器通过 13 项回归，覆盖区域独立取样、圆角残边、前景不透明、编辑退出、文件事务及继承切换。真实首页、设置、角色列表、创建对话和通用背景编辑器完成浅深主题截图检查，临时截图代码不纳入仓库。其他 Android 版本尚未逐版本实机复核。
